# maintain: 検知を intent に戻す(Maintain)

人間が本番を見張る代わりに、エージェントが監視し、逸脱を**新しい intent.md としてパイプラインの先頭に書き戻す**。これでループが閉じる。

## 1. 逸脱検知と段階的対応

- **検知は決定的に**: LLM に「おかしいか」を判断させない。メトリクス(CI 失敗率、デプロイ後の 5xx 率など)をローリングベースラインと比較し、Western Electric ルールのような統計ルールで判定する
- **対応段階はバージョン管理された設定で定義する**: [references/detector-config.example.yaml](references/detector-config.example.yaml)
  - 1σ: ログに残すだけ
  - 2σ: 読み取り専用で診断する
  - 3σ: 修正 PR を提案する、または事前承認済みのランブックを実行する
- **Claude はステートレス・ヘッドレスで実行**し、診断結果を `intent.md`(`source: detector`)として書く。その intent は通常の `intent` → `spec` → `plan` の流れに再投入される

### 診断を intent にするときの書き方

`intent` スキルのテンプレートを使い、以下を必ず含める:

- 検知したメトリクス、閾値、発生時刻、ベースライン
- 読み取り専用で確認した事実(ログ、直近のデプロイ、関連コミット)と、推測を分けて書く
- 推奨する次の一手(調査継続 / 修正 PR / ロールバック)

## 2. 定期コードベーススキャン

- セキュリティスキャンを定期実行する(Claude Security のようなホスト型でも、スケジュール実行の Claude Code でもよい)
- 検出は検証済み・確信度付きで出す
- 小さな修正 → 通常の PR レビューへ
- 大きな問題 → `intent.md` として起票
- **却下するときは理由を必須にする**(記録が残るように)

## 3. インシデント対応

- Claude をインシデントチャンネルの参加者として入れる(例: Claude Tag in Slack)。診断し、MCP 経由で復旧を確認し、ポストモーテムを書く
- ポストモーテムの教訓は、バージョン管理された教訓ファイル(例: `docs/lessons.md`)に追記する
- チャンネルそのものを監査証跡として扱う
- 各インシデントは:
  - `verify-loop` の eval に 1 件追加する
  - 再発防止策が必要なら intent として起票する
  - Claude の誤りが原因なら CLAUDE.md / hook に反映する

## 進め方

1. 何を監視したいか(メトリクスとデータソース)をユーザーと決める
2. 検知設定と段階的対応を設定ファイルとして作る
3. 2σ / 3σ 時に起動するヘッドレス実行(CI のスケジュールジョブ等)と、そのプロンプト(「読み取り専用で診断し、intent.md を書いて PR を出す」)を作る
4. 3σ の自動アクションは、`guardrails` の「本番ゲートを越えない」原則に従って権限を絞る

## 測定

- 逸脱 → intent までの時間
- 検出がマージ済みの修正になった割合
- インシデント再発率、スキャンのカバレッジ、検出件数の推移
