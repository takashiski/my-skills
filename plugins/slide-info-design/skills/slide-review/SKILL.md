# slide-review: 情報デザインの観点でスライドをレビューする

出典: 天野由貴『情報デザインを意識したスライド作成入門』(CC BY-SA 4.0)。
基準は [../slide-design/references/checklist.md](../slide-design/references/checklist.md)。根拠の詳細は同じディレクトリの `charts.md` / `typography.md` / `color.md` / `copyright.md`。

## 手順

1. **読み込む**
   - `.pptx`: テキスト・フォント名とサイズ・行間・図形の塗り/枠線・グラフ種類・色を抽出する(python-pptx 等。pptx スキルがあればそれに従う)。
   - PDF / 画像: ページを画像として見て判断する。フォントサイズは文字高さから推定し、推定であることを明記する。
   - Marp / HTML: ソースと CSS を読む。可能ならレンダリングして見た目も確認する。
2. **全体を見る**: 発表全体のメッセージ、枚数と持ち時間(1 枚約 1 分)、配色が 3 色程度か、最後がまとめスライドか。
3. **1 枚ずつ見る**: チェックリスト B〜G を当てる。各スライドについて「このスライドで伝えたいこと」を 1 文で言えるか試し、言えなければ A1 違反として扱う。
4. **報告する**(下の形式)。
5. 依頼されていれば修正する。修正後に該当項目を再チェックする。

## 指摘の重要度

- **重要**: 誤解を招く / 読めない。例: 棒グラフの軸が 0 でない(D2)、3D グラフ(D7)、28pt 未満の本文(E1)、背景と文字のコントラスト不足(F5)、色だけに頼った見分けにくい区別(F6)、出典なしの他人の著作物(G1)、1 枚に複数メッセージの詰め込み(A1/A2)
- **改善**: 伝わりにくくしている。例: センタリング本文、余白不足、不要な枠線・装飾、色数過多、目盛線過多
- **軽微**: 好みに近いもの。数は絞る(全体で 5 件程度まで)

## 出力形式

```markdown
## 総評
- 全体メッセージ: …(読み取れた主張。読み取れなければそう書く)
- 良い点: …
- 優先して直すべき 3 点: …

## スライド別
### p.3 「〇〇」
- [重要][D2] 棒グラフの縦軸が 20 から始まっており、2011→2013 が実際(30→40)より大きな伸びに見える → 縦軸を 0 から始める
- [改善][B5] 本文がセンタリング → 左揃えにする
```

- 指摘には必ずチェックリスト ID と、**何が起きているか → どう直すか** を書く。
- 「見にくい」のような印象だけの指摘はしない。どの原則に反し、聴衆に何が起きるかを書く。
- 良い点も挙げる(残すべき判断を消さないため)。
